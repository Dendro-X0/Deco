# v0.6.x continuation — Scan strategy & performance tuning

**Status:** In progress (`v0.6.9` shipped; **`v0.6.10`** Bazel + native global caches — see [v0.6.10-manifest.md](v0.6.10-manifest.md))  
**Intent:** Stay in **Phase C** (scan engine) before jumping to `v0.7.x` trust/community work. Let users pick strategies that match their machine, and iterate on statistics and cleanup UX with measured experiments.

**Shipped in 0.6.x so far:** pipelined scan (`v0.6.0`), incremental inventory + Quick update (`v0.6.1`), maintainer benchmarks (`v0.6.2`).

---

## North star for remaining 0.6.x

1. **Transparent performance** — users see what each phase costs and can trade speed vs thoroughness.  
2. **Configurable engine knobs** — search/discovery strategy and parallelism live in **Settings**, not hidden in code.  
3. **Evidence-based changes** — `deco-bench` + manual notes before promoting experiments.  
4. **No safety regression** — new “fast” modes must not increase blocked-path or false-safe deletes.

---

## Proposed themes (not yet versioned)

### S1 — Scan strategy presets (Settings)

| Preset | Discover | Classify / size | Best for |
|--------|----------|-----------------|----------|
| **Thorough** | Full walk, all enabled discovery flags | Default pipeline, `scan_concurrency_mode: auto` | First scan, audit |
| **Balanced** | Same as today default | Pipelined + inventory Quick update | Daily use |
| **Fast** | Shallower depth optional; skip optional global caches | Higher concurrency cap, smaller classify chunks | NVMe, repeat scans |
| **Background** | `low` concurrency, longer size timeouts tolerated | Minimal UI churn | HDD, laptop on battery |

**Deliverable shape:** `scan_strategy: thorough | balanced | fast | background` maps to bundles of existing settings (`max_depth`, `scan_concurrency_mode`, `incremental_inventory_enabled`, discovery toggles) — not a second engine.

### S2 — Threading & concurrency (Settings expansion)

- Surface **`scan_concurrency_mode`** next to new strategy preset (already exists; group in UI).  
- Optional **classify parallelism** toggle or cap (today: rayon when chunk ≥ 8, fixed threshold).  
- Optional **discover parallelism** (today: multi-root only) — document limits on HDD.  
- **Advanced** drawer: numeric overrides for power users (behind `advanced_mode`).

### S3 — Statistics & progress

- Status line: phase breakdown (already partial via `discover_ms` / `classify_ms` / `size_ms`).  
- Post-scan summary card: time per phase, reuse % on Quick update, candidates by kind.  
- Optional export snippet for support (copy diagnostics).

### S4 — Cleaning strategy experiments

- Batch sizing hints from scan stats (“largest safe wins first”).  
- Sort presets tied to strategy (size-first vs risk-first).  
- No auto-delete without review — experiments stay suggest-only until `v0.7` trust work.
