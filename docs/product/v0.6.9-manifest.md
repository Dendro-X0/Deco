# v0.6.9 manifest — C++ / native build ecosystem breadth

**Status:** Shipped (`v0.6.9`)  
**Target release:** `v0.6.9`  
**Theme:** Expand deterministic discovery for CMake, Meson, MSVC, and IDE-side native build folders without widening to open-world “large folder” heuristics.

Parent: [v0.6.x-roadmap.md](v0.6.x-roadmap.md) · Builds on `v0.6.8` (update UX + CI fixes).

---

## Problem

Developers on **C++ / native** stacks still hit gaps: Meson default out-of-tree dirs, CMake `out/` on balanced profiles, and Visual Studio `.vs/` IDE caches are missed or treated like generic `build/` trees. We need marker-gated rules with the same safety bar as existing `cmake-build-*` / MSVC config detection.

## Deliverables

| ID | Deliverable | Acceptance |
|----|-------------|------------|
| **N1** | **Meson build dirs** | `builddir` / `_build` discovered when `meson.build` exists on an ancestor (`balanced+`) |
| **N2** | **CMake `out/` (balanced+)** | `out/` discovered when `CMakeLists.txt` or `CMakeCache.txt` on ancestor (not aggressive-only) |
| **N3** | **Visual Studio `.vs/`** | `.vs/` discovered when `.sln` / `.vcxproj` on ancestor; classified **review** (IDE index, not just compile output) |
| **N4** | **Native marker union** | `meson.build` counts toward native-build ancestor checks (with CMake / MSVC markers) |
| **N5** | **Parity + tests** | Shipped — Rust + CLI parity; `pnpm check` green |

## Non-goals (0.6.9)

- Bazel / vcpkg / Conan global caches (defer to `v0.6.10` or `v0.7`)  
- New `schema_version` unless wire shape changes  
- Auto-delete or new risk tiers beyond review on `.vs/`
