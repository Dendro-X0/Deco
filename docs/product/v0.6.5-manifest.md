# v0.6.5 manifest — Smart discovery patterns + classify parallelism

## Problem

Explicit per-tool discovery does not scale to every IDE and mobile SDK. Classify parallelism is fixed at 8 targets (rayon gate). Users need safe extension points without abandoning the whitelist model.

## Deliverables

| ID | Deliverable | Acceptance |
|----|-------------|------------|
| **D1** | `smart_discovery_enabled` (default off) | Settings → Discovery; scan honors flag |
| **D2** | `discovery_patterns` module | Pattern table maps path signals → existing `Kind` |
| **D3** | IDE patterns (Android Studio + JetBrains `caches`) | With IDE global cache opt-in, paths appear as `ide_global_cache` |
| **D4** | `classify_parallel_threshold` (default 8, advanced UI) | Rayon classify only when chunk ≥ threshold |
| **D5** | Experiment doc + Rust tests for patterns | `smart-scan-strategy.md`; `discovery_patterns` unit tests |
| **D6** | Bench / CI unchanged or note in CHANGELOG | `pnpm benchmark:scan` still passes |
| **D7** | `fast_tree_delete_enabled` (default on, experimental) | In-place `node_modules` delete uses `rmdir` / `rm -rf`; Settings → Safety |

## Non-goals

- New wire kinds for Android SDK / AVD (separate 0.5.x / 0.7 items)  
- LLM or content-based classification  
- OS-wide “C drive cleaner” mode  
- CLI parity for smart discovery in 0.6.5

## Verification

```bash
pnpm check
```

Manual: enable **Smart discovery** + **IDE global cache** → scan profile with Android Studio installed → `caches` under Android Studio appears (review). Toggle **classify parallel threshold** in Advanced → large scans show classify timing shift (optional).
