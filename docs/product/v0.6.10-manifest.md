# v0.6.10 manifest — Bazel + native global caches

**Status:** In progress  
**Target release:** `v0.6.10`  
**Theme:** Continue C++/native ecosystem breadth with Bazel workspace outputs and opt-in global compiler/package caches.

Parent: [v0.6.x-roadmap.md](v0.6.x-roadmap.md) · Builds on [v0.6.9-manifest.md](v0.6.9-manifest.md).

---

## Problem

After v0.6.9, project-local Meson/CMake/MSVC coverage improved, but **Bazel** trees and **shared compiler caches** (ccache, sccache) plus **vcpkg/Conan** global stores were still invisible unless users manually browsed disks.

## Deliverables

| ID | Deliverable | Acceptance |
|----|-------------|------------|
| **B1** | **Bazel `bazel-*` dirs** | Discovered when `WORKSPACE` / `WORKSPACE.bazel` / `MODULE.bazel` on ancestor (`balanced+`) |
| **G1** | **vcpkg installed tree** | `VCPKG_ROOT/installed` (or `~/vcpkg/installed`) with `.vcpkg-root` / `vcpkg.json` marker on parent |
| **G2** | **Conan 2 package cache** | `CONAN_HOME` or `~/.conan2/p` with Conan home markers |
| **G3** | **ccache** | `CCACHE_DIR` or default OS paths; `stats` file or cache layout marker |
| **G4** | **sccache** | `SCCACHE_DIR` or `~/.cache/sccache` with `cache/` subdir |
| **G5** | **Contract + UI + CLI** | `schema_version` **2.7.0**; Settings discovery toggles; execute guard matches scan flags |
| **G6** | **Tests** | Rust + CLI integration; `pnpm check` green |

## Non-goals (0.6.10)

- Bazel external/remote cache roots outside workspace  
- Deleting entire vcpkg root (only `installed/` tree)  
- Auto-delete on global caches

pnpm check
