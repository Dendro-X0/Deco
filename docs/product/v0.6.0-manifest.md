**Status:** Shipped (2026-05-15)  
**Release:** `v0.6.0`  
**Theme:** Faster wall-clock and perceived scan time on HDD, SSD, and NVMe without changing safety defaults or scan contract shape (no `schema_version` bump unless noted).

Parent plan: [version-roadmap.md](version-roadmap.md) Phase C · Benchmark notes: [../experiments/scan-performance.md](../experiments/scan-performance.md).

## Problem statement

On large data drives (e.g. `E:\`), **directory discovery** often finishes in tens of seconds while **classify + size + UI sort** consume the rest of the scan. Size walks are disk-bound; classify does per-candidate project-marker lookups; sizing already uses rayon but with a **fixed** concurrency that can hurt HDDs or under-use NVMe.

Goals for `v0.6.0`:

1. **Overlap work** — classify and size in chunks so bytes appear sooner.  
2. **Use CPU where it helps** — parallel classify + project-root memoization.  
3. **Adapt to hardware** — `scan_concurrency_mode`: `auto` | `low` | `high`.  
4. **Measure** — phase timings in progress events for tuning and support.

**Non-goals (0.6.0):** incremental inventory DB (`v0.6.1`), Windows USN journal (`experimental` later), GPU, duplicate-content hashing.

## Technical design

### Pipeline (C1)

```
discover (existing walker + prune)
    ↓
for each chunk of N targets (N ≈ 64):
    classify_chunk_parallel (C2)
    emit scan-candidate-batch (phase=classify)
    if include_size:
        size_chunk (C3 concurrency plan)
        emit scan-candidate-batch (phase=size)
aggregate → persist → scan-complete
```

Cancel semantics unchanged: discovery cancel vs sizing cancel (`scan_cancel.rs`).

### Classify (C2)

- Extract `classify_discovered_target(..., cache: &mut ProjectRootCache)`.
- `ProjectRootCache` memoizes `detect_project_root` by `(start_dir, stop_root)` key.
- Chunks use `rayon` when `len >= 8` with `Mutex<ProjectRootCache>`.

### Size concurrency (C3)

| Mode | `batch_size` | `max_in_flight_batches` | Intent |
|------|----------------|-------------------------|--------|
| `low` | 8 | 1 | HDD-friendly, background use |
| `auto` | 25 | `clamp(2, cpus/2, 6)` | Default |
| `high` | 32 | 8 | Fast SSD / many roots |

Total in-flight size tasks ≈ `batch_size × max_in_flight_batches` (same structure as today, tunable).

### Progress (C4)

Extend `ScanProgressEvent` (backward-compatible optional fields):

- `discover_ms`, `classify_ms`, `size_ms` — cumulative phase milliseconds at emit time.
