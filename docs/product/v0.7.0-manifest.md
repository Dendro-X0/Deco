# v0.7.0 manifest — Profiles + regeneration hints (draft)

**Status:** In progress  
**Target release:** `v0.7.0`  
**Theme:** Phase D trust work — preset **cleanup profiles** for common roles and **regeneration hints** surfaced in the desktop UI (engine/CLI already carry hint text for global caches).

Parent: [v0.7.x-roadmap.md](v0.7.x-roadmap.md) · Follows [v0.6.12-manifest.md](v0.6.12-manifest.md).

---

## Problem

- **Scan strategy** presets (`thorough` / `balanced` / …) tune depth and concurrency only; they do not help users pick roots, discovery flags, or safety profile for “first audit” vs “monorepo maintainer” vs “CI agent”.
- **Regeneration hints** exist in Rust (`regeneration_hints.rs`) and CLI (`regeneration-hints.ts`) but are not shown in candidate detail in the desktop app.

## Deliverables

| ID | Deliverable | Acceptance |
|----|-------------|------------|
| **P1** | **Cleanup profiles** | Named presets (e.g. first scan, monorepo maintainer, CI agent) apply a documented bundle of settings: roots/scope hints, `profile` / `stale_days`, selected global `check_*` flags, optional `scan_strategy`; user can still override and land on `custom` |
| **R1** | **Regeneration hints in UI** | Candidate detail shows “Regenerate: …” when `regeneration_hint_for_kind` applies; parity with CLI/Rust strings for global-cache kinds |
| **D1** | **Docs + tests** | Manifest checklist; unit tests for profile bundles and hint wiring; [CHANGELOG.md](../../CHANGELOG.md) [Unreleased] |

## Non-goals (defer to later 0.7.x)

- **Dormancy ranking** (`v0.7.1`) — mtime / optional git last-commit; explain-only  
- **Policy packs** (`v0.7.2`) — validated `.deco` snippets + CLI validator  
- Community profile marketplace; lowering review tier; auto-delete  
- New `schema_version` unless scan report wire shape changes

## Verification

```bash
pnpm check
```

Manual: apply each profile in Settings → save → scan → open a global-cache candidate → regeneration line visible.
