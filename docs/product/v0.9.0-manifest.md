## v0.9.0 manifest — Secure directory migration (Windows)

**Status:** In progress (development head; not tagged for production yet)  
**Target release:** `v0.9.0`  
**Theme:** Move high-churn tool directories off constrained OS drives (e.g. `C:`) with **safe, auditable, rollbackable** migration.

This release explicitly targets the “small OS drive” failure mode: developer tools silently accumulating gigabytes under `%APPDATA%`, `%LOCALAPPDATA%`, and `C:\ProgramData`, eventually breaking normal development workflows.

Parent: [version-roadmap.md](version-roadmap.md) · Follows `v0.8.5` (latest **production** tag).

**Ship when:** all checklist items below are done and `pnpm check` is green — then tag `v0.9.0` and publish installers.

---

### Principles (must hold)

- **No guess-delete:** Migration is an alternative to deletion, not a new destructive cleanup heuristic.
- **Safety-first:** Prefer an all-or-nothing approach with rollback on failure.
- **Least privilege:** Work in user-writable locations without elevation where possible; when elevation is required, detect early and provide clear instructions.
- **Auditability:** Every migration writes a machine-readable log with enough detail to diagnose or undo.
- **Predictability:** Deterministic source/destination mapping; no hidden “smart paths.”

### Scope detail

#### M1 — Migration primitive (native / Windows)

- Plan: resolve paths, size estimate, nesting checks, junction-source refusal, **NTFS dest check**
- Execute: copy → rename backup → `mklink /J` → verify → remove backup; rollback on failure

#### M2 — CLI surface

```bash
deco migrate-tool-dir plan --tool cursor --dest-root "G:/DevToolData"
deco migrate-tool-dir run  --tool cursor --dest-root "G:/DevToolData" --yes
deco migrate-tool-dir plan --source "..." --dest "..." --json
```

#### M2b — Desktop surface (Settings)

Settings → **Tool storage migration (Windows)** — Plan / Run with folder picker and audit log path.

#### M3 — Tool profiles

| Tool | Source (default) | Run |
|------|------------------|-----|
| `cursor` | `%APPDATA%\Cursor` | Yes |
| `vscode` | `%APPDATA%\Code` | Yes |
| `docker-desktop` | `%LOCALAPPDATA%\Docker` (guidance) | Plan only |

**Note:** Cursor also uses `%LOCALAPPDATA%\Cursor` for caches; v0.9.0 migrates Roaming only. Follow-up: optional `cursor-local` profile.

---

### Security & abuse resistance

- Blocked system roots and drive roots
- Refuse migrating an existing junction/symlink source (no `--force` in v0.9.0)
- Audit logs: paths only, no file contents

---

### Manual QA (release gate)

Before tagging `v0.9.0`:

1. Quit Cursor completely.
2. Settings → Tool storage migration → Plan (`cursor`, dest root e.g. `G:\DevToolData`).
3. Confirm dest is `G:\DevToolData\Cursor` and plan is **ok**.
4. Run migration; confirm audit log path.
5. Restart Cursor — settings, extensions, chat history intact.
6. Confirm `C:\Users\…\AppData\Roaming\Cursor` is a junction (not multi-GB folder).
7. Confirm free space reclaimed on `C:`.

---

### Non-goals

- Docker image/volume pruning
- Migrating arbitrary user folders without explicit paths
- Silent background migration
