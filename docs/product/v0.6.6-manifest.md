# v0.6.6 manifest — Large-scan UX & HDD cleanup strategy

**Status:** In progress  
**Target release:** `v0.6.6`  
**Theme:** Make huge result sets and slow disks manageable without changing safety defaults.

Parent: [v0.6.x-roadmap.md](v0.6.x-roadmap.md) · Builds on `v0.6.5` fast delete, coalescing, and accurate scan progress.

---

## Problem

Full-drive scans can surface **thousands** of `node_modules` rows. The UI, size phase, and delete pipeline still behave like “hundreds of items” workloads. On HDDs, parallel deletes and per-tree walks degrade non-linearly. Users need clearer grouping, honest progress, and cleanup strategies tuned for mechanical disks.

## Deliverables (draft)

| ID | Deliverable | Acceptance |
|----|-------------|------------|
| **L1** | **Project-root grouping** in results (optional view) | List collapses to one row per project with child artifact summary; expand for detail |
| **L2** | **HDD cleanup mode** | Detect or user-select: lower delete parallelism, sequential option, pause/resume queue |
| **L3** | **Quick-update benchmark** | `deco-bench` or CI case: unchanged tree ≥30% faster than full scan |
| **L4** | **Size phase optimizations** | Optional fast estimate for `node_modules` (sampling / shallow walk); fewer 30s timeouts on huge trees |
| **L5** | **Batch delete UX** | Chunked delete with cancel between chunks; progress shows throughput estimate |
| **L6** | Docs + tests | Experiment notes; `pnpm check` green |

## Non-goals

- Auto-delete without review  
- New `schema_version` unless response shape changes  
- OS journal / USN-based discover skip (later track)

## Verification

```bash
pnpm check
pnpm benchmark:scan
```

Manual: scan a drive with 500+ `node_modules`; toggle project view; run cleanup on HDD with HDD mode — progress and cancel behave predictably.
