# v0.6.7 manifest — Scan speed & delete throughput

**Status:** In progress  
**Target release:** `v0.6.7`  
**Theme:** Measure and improve repeat-scan and size-phase performance; smarter batch delete feedback.

Parent: [v0.6.x-roadmap.md](v0.6.x-roadmap.md) · Builds on `v0.6.6` project grouping and HDD cleanup mode.

---

## Problem

Large scans still spend disproportionate time in **size** walks and repeat **Quick update** paths. Bulk deletes on huge selections need clearer throughput and chunk boundaries without weakening review gates.

## Deliverables (draft)

| ID | Deliverable | Acceptance |
|----|-------------|------------|
| **L3** | **Quick-update benchmark** | `deco-bench` or CI case: unchanged tree ≥30% faster than full scan |
| **L4** | **Size phase optimizations** | Optional fast estimate for `node_modules` (sampling / shallow walk); fewer 30s timeouts on huge trees |
| **L5** | **Batch delete UX** | Chunked delete with cancel between chunks; progress shows throughput estimate |
| **L6** | Docs + tests | Experiment notes; `pnpm check` green |

## Non-goals

- Auto-delete without review  
- New `schema_version` unless response shape changes  
- OS journal / USN-based discover skip (later track)

## Verification

```bash
pnpm check
pnpm benchmark:scan
```

Manual: run Quick update twice on an unchanged tree; confirm bench documents ≥30% win; delete 500+ safe rows and observe chunk progress + cancel between chunks.
