# v0.6.7 manifest — Scan speed & delete throughput

**Status:** Shipped (`v0.6.7`)  
**Target release:** `v0.6.7`  
**Theme:** Measure and improve repeat-scan and size-phase performance; smarter batch delete feedback.

Parent: [v0.6.x-roadmap.md](v0.6.x-roadmap.md) · Builds on `v0.6.6` project grouping and HDD cleanup mode.

## Problem

Large scans still spend disproportionate time in **size** walks and repeat **Quick update** paths. Bulk deletes on huge selections need clearer throughput and chunk boundaries without weakening review gates.

## Deliverables

| ID | Deliverable | Acceptance |
|----|-------------|------------|
| **L3** | **Quick-update benchmark** | Shipped — `deco-bench --quick-update`, `pnpm benchmark:quick-update`, CI + `baseline.quick-update.json` |
| **L4** | **Size phase optimizations** | Shipped — `fast_dependency_size_estimate`; package sampling + capped walks; `size_estimated` / `~` in UI |
| **L5** | **Batch delete UX** | Shipped — 80+ trees → 40/chunk; cancel/pause between chunks; `chunk_boundary` + throughput in progress |
| **L6** | Docs + tests | Shipped — experiment index; `pnpm check` green; CI scan + quick-update benches |

## Non-goals

- Auto-delete without review  
- New `schema_version` unless response shape changes  
- OS journal / USN-based discover skip (later track)

## Verification

```bash
pnpm check
pnpm benchmark:scan
pnpm benchmark:quick-update
```

| Check | Command | Notes |
|-------|---------|--------|
| Typecheck + lint + unit tests | `pnpm check` | CLI + Rust (includes `cleanup_batch`, `cleanup-progress`) |
| Synthetic scan regression | `pnpm benchmark:scan` | `benchmarks/baseline.synthetic.json` |
| Quick-update gates | `pnpm benchmark:quick-update` | ≥30% classify+size speedup, ≥95% inventory reuse |
| Chunk delete constants | `cargo test cleanup_batch` | Threshold 80, chunk size 40, throughput formatting |

**Manual**

1. Quick update twice on an unchanged tree — second run faster; status shows reuse.  
2. Delete 80+ safe bulk trees — `chunk_boundary` progress with `folders/min` / `MB/s`; **Stop** between chunks cancels before the next batch.  
3. Large `node_modules` size — `~` prefix when estimate applies (`size_estimated`).
