# v0.9.8 manifest — Custom folder migration

**Status:** Shipped (`v0.9.8`)  
**Target:** Windows NTFS junction migrations (same engine as v0.9.x profiles)

---

## Goal

Let users migrate **arbitrary folders** off the OS drive when no pre-configured profile exists — e.g. game mod directories scattered under `Documents` or `AppData` — while **blocking unsafe paths** (system dirs, entire profile roots).

Example: `Documents\Electronic Arts\The Sims 4\Mods` → `G:\Games\Sims4\Mods`.

---

## Scope

| ID | Feature | Notes |
|----|---------|--------|
| **C1** | Custom mode in Settings → Tool storage migration | Source + destination folder pickers; Plan + Run |
| **C2** | Path blocklist (denylist) | Block `Windows`, `Program Files`, `ProgramData`, drive roots, and **entire** `Documents` / `AppData` / profile roots; allow specific subfolders |
| **C3** | Destination verification on re-plan | Same as v0.9.7 for custom paths (junction + dest scan) |
| **C4** | CLI parity | `migration-path-policy.ts` shared rules; `--source` / `--dest` unchanged |
| **C5** | Docs | This manifest; update `tool-migration-profiles.md` custom section |

## Out of scope (v0.9.8)

- Multi-leg custom bundles (one source only per run)
- Registry / launcher path rewrites (user keeps junction at original path)
- Non-Windows platforms

---

## Safety blocklist (summary)

**Blocked as source or destination:**

- Drive roots (`C:\`)
- Anything under `%SystemRoot%`, `%ProgramFiles%`, `%ProgramFiles(x86)%`, `%ProgramData%`
- Exact profile roots: `%USERPROFILE%`, `%USERPROFILE%\Documents`, `%USERPROFILE%\AppData`, `%USERPROFILE%\AppData\Roaming|Local|LocalLow`, Desktop, Downloads, etc.

**Allowed examples:**

- `%USERPROFILE%\Documents\Electronic Arts\The Sims 4\Mods`
- `%APPDATA%\obs-studio` (specific app folder)
- `G:\Games\Sims4\Mods`

Implementation: `apps/desktop/src-tauri/src/util/migration_path_policy.rs`, `apps/cli/src/migration-path-policy.ts`.
