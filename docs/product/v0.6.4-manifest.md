# v0.6.4 manifest — Scan statistics panel

**Status:** Shipped (`v0.6.4`)  
**Target release:** `v0.6.4`  
**Theme:** Make scan performance and results transparent after each run.

Parent: [v0.6.x-roadmap.md](v0.6.x-roadmap.md) · Builds on phase timings from v0.6.0 and inventory reuse from v0.6.1.

---

## Problem

Phase timings exist in engine events but are easy to miss in the status line. Users cannot see **where time went**, **Quick update reuse %**, or **which artifact kinds dominate** without digging into the candidate table.

## Deliverables

| ID | Deliverable | Acceptance |
|----|-------------|------------|
| **T1** | `discover_ms` / `classify_ms` / `size_ms` on `ScanResponse` | Returned on `scan-complete` with report |
| **T2** | `scan-statistics.ts` helpers | Phase %, top kinds, reuse %, diagnostics text |
| **T3** | **Scan statistics** dashboard card after scan | Phase bars + kind breakdown + reuse when applicable |
| **T4** | Status footer shows phase timing when idle after scan | Compact discover / classify / size line |
| **T5** | Copy diagnostics | Clipboard snippet for support |
| **T6** | Tests + CHANGELOG | `scan-statistics.test.ts` |

## Non-goals

- Persist timings in scan history DB (v0.6.5+).  
- Classify parallelism cap (v0.6.5).  
- Export to file.

pnpm check
