# v0.6.3 manifest — Scan strategy presets

**Status:** Shipped (`v0.6.3`)  
**Target release:** `v0.6.3`  
**Theme:** Let users pick a scan performance profile that maps to existing engine settings.

Parent: [v0.6.x-roadmap.md](v0.6.x-roadmap.md) · Engine unchanged (no new scan phases).

---

## Problem

Power users can tune `max_depth`, `scan_concurrency_mode`, and Quick update — but most people need a single control: **“how hard should this machine work?”**

## Deliverables

| ID | Deliverable | Acceptance |
|----|-------------|------------|
| **S1** | `scan_strategy` on Settings (`thorough` \| `balanced` \| `fast` \| `background` \| `custom`) | Persisted in SQLite settings JSON |
| **S2** | Preset bundles apply tuning keys on select | Changing preset updates depth + concurrency + inventory flag |
| **S3** | Manual tuning sets `custom` when bundle no longer matches | Derive on depth/concurrency/inventory change |
| **S4** | Dashboard shows active strategy summary | One line under Scan targets |
| **S5** | Settings UI groups strategy + performance | Strategy first; concurrency/inventory under same section |
| **S6** | Tests + docs | `scan-strategy.test.ts`; CHANGELOG + manifest |

## Preset bundles

| Preset | max_depth | scan_concurrency_mode | incremental_inventory |
|--------|-----------|------------------------|------------------------|
| Thorough | 10 | auto | on |
| Balanced | 8 | auto | on |
| Fast | 6 | high | on |
| Background | 5 | low | on |

Discovery flags and safety profile are **unchanged** by presets (v0.6.3 scope).

## Non-goals

- Classify parallelism cap (v0.6.5).  
- Post-scan statistics panel (v0.6.4).  
- Engine reads strategy string directly (bundles only affect stored settings).

## Verification

```bash
pnpm check
```

Manual: switch presets in Settings → Save → Dashboard summary updates → Scan Now / Quick update behave as before with new tuning.
